# 辣度风险词表（risk-glossary）

> **这不是营养或配料数据，是风险分层规则。**
> MCP 的 `query-meals` 只返回 `name / currentPrice / originalPrice / tags / discountType / canWithOrder / image`，
> **没有辣度、配料、过敏原、热量字段**。所以本文件做的是「哪类商品不能给忌口的人」，不是「哪类商品不辣」。

---

## 1. 四档定义

| 档位 | 判定 | 严格方案 | 待确认方案 | 输出措辞 |
|---|---|---|---|---|
| **高** | 名称或 tags 强命中辣味词 | ❌ 排除 | ❌ 排除 | 「含辣味特征，已排除」 |
| **疑似** | 弱命中（风味词可能含辣） | ❌ 排除 | ⚠️ 可列 | 「风味描述可能含辣，需确认」 |
| **未知** | 无任何辣度信号（**默认档**） | ❌ 排除 | ⚠️ 可列 | 「无法从官方数据判定辣度」 |
| **用户确认** | 用户明确说「这个我吃过 / 可以接受」 | ✅ 保留 | ✅ 保留 | 「已由你确认」 |

> **没有「低风险」这一档。** 名称里没有「辣」字，是「未知」，不是「不辣」。

---

## 2. 关键词表

### 2.1 强命中 → 高风险

| 关键词 | 实测命中示例 |
|---|---|
| `麦辣` | 麦辣鸡腿堡、麦辣鸡翅4块中套餐 |
| `香辣` `劲辣` `超辣` `麻辣` | — |
| `川香` | — |
| `龙焰` | 龙焰鸡腿堡（tags: 上新、韩式辣椒黄油风味） |
| `椒盐` | — |
| `藤椒` | — |
| `辣椒` | 5块心形薯饼+**韩式辣椒**黄油风味酱 |
| `辣酱` | 同上 |
| `韩式` + `辣` / `辣` + `黄油` | 韩式辣椒黄油风味 |

**判定口径**：命中任一即「高」。**无需人工复核，命中即排除。**

### 2.2 弱命中 → 疑似

| 关键词 | 理由 |
|---|---|
| `黑椒` `奥尔良` `卡真` `墨西哥` `芥末` `咖喱` `烧烤` `孜然` | 风味可能带轻微刺激，官方无辣度声明 |
| `椒` 单字（非「椒盐」「藤椒」组合） | 需人工看一眼全名 |

### 2.3 无信号 → 未知（绝大多数）

例：巨无霸、板烧鸡腿堡、麦乐鸡、双层吉士堡、薯条、玉米杯、可乐、纯牛奶、苹果汁……

**这些全部是「未知」，不是「不辣」。** 哪怕你「知道」巨无霸不辣，也不能替用户下结论——只能问用户。

---

## 3. 「用户确认」的使用规则

这是唯一合法的放行通道。

**问法**（必须原话问到，不能自己替用户答）：

> 「X 的辣度在官方数据里查不到。你之前吃过 `板烧鸡腿堡` 吗？如果确认没问题，我按『你已确认』处理，并会在结果里标注这是你的确认，不是官方数据。」

**限制**：

1. 只对该**成员**、该**商品**生效，不能扩散到同品类
2. 输出时必须标注来源 = 用户确认，**不得混入官方数据栏**
3. 用户没确认就不能放行；宁可输出「无可验证方案」

---

## 4. 两个高频错误

### 4.1 「去酱就不辣」——错

`9900004002` 麦辣鸡腿汉堡的特调只有两项：去「麦香鸡酱」、去「切块生菜」。

**辣味来自腌料和辣酱配方，去酱不等于去辣。** 任何「特调降辣」的推断都不成立，禁止输出。

### 4.2 「板烧/巨无霸是经典款所以不辣」——错

这是模型常识，不是官方数据。MCP 里没有这个字段。按 §2.3 一律判「未知」。

---

## 5. 过敏原

**完全不参与求解。**

- 不读取、不推断任何配料的过敏原
- 不做品牌级安全保证（「麦当劳的薯条不含麸质」这类话一律禁止）
- 统一输出：「本单含以下商品，过敏原信息 MCP 未提供，请到店或官方渠道确认配料后再下单。」

如果某成员有严重过敏（花生、坚果、海鲜、麸质等），在输出开头单独加一条**醒目提示**，并建议其单独点单以降低交叉污染风险。

---

## 6. 维护方式

新增商品时只需跑一遍 `query-meals`，对每个 `name + tags` 做关键词匹配：

```
命中 §2.1 → 高
否则命中 §2.2 → 疑似
否则 → 未知
```

规则式判定，**不依赖人工逐个标注**，因此可复现、可复算。
